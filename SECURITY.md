# Security policy

## Supported versions

Until the first stable release, security fixes are made on the latest published minor version only. After 1.0, the current major version will receive security fixes; older versions may be evaluated case by case.

## Reporting a vulnerability

<!-- Maintainer: replace security@example.com with a monitored private address before publishing. -->

Email **security@example.com** with the affected package and version, impact, reproduction or proof of concept, relevant environment details, and any suggested mitigation. Please do not open a public issue or disclose the vulnerability before coordinated disclosure.

We will acknowledge reports as soon as practical, keep reporters informed while validating and fixing the issue, and coordinate a disclosure date and credit preference. Never include real user data or secrets in a report.
